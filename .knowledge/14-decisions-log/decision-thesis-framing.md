# Decision: Thesis Framing: Protocol-Level Evaluation

## Context

How to frame the thesis contribution

## Analysis

Initial framing: 'Is MCP better than code generation?' — too binary, answer is 'it depends'. Round 2 literature (Hou TOSEM, Fan AAMAS, Ehtesham survey) supports protocol-level evaluation framing: interoperability, planning, parameterization, output validity, security.

## Decision

Frame as: 'How does MCP as a tool-integration protocol affect interoperability, planning, parameterization, output validity, and security in GIS automation?' 5 evaluation dimensions. Positions thesis at protocol level, not just tool comparison.

## Rejected Alternative

Binary comparison framing (original)

## Rationale

Too simplistic; doesn't capture multi-dimensional reality

## Impact

## Reversibility

Low — framing change, same data
